# 自动 RSS 与投递运行时阶段验证

日期：2026-10-23（Asia/Hong_Kong）。本轮把 RSS 调度、规则匹配、多个显式配置的 qui 实例、容量证据与暂停 Add 接入常驻运行时。验证结论分为本地模拟服务验收、真实只读检查和真实自动 Add，三者不互相替代。

## 已完成的运行时能力

- RSS 首次拉取建立基线，保存轮询时间和 HTTP 缓存字段；重启后按 feed 周期继续轮询，停用站点不继续读取。RSS 查询参数在创建和更新时保留，拒绝 URL userinfo、fragment、非法转义和非 HTTP(S) scheme。
- 多实例配置各自绑定代理凭据、同步状态、存储目标与投递 worker，只处理规则明确指定的固定实例。所有实例和 scheduler 初始化成功后才启动投递 worker。
- 投递前重新下载并校验 torrent 身份、大小及固化规则决策，经 qui 采集完整同步快照、默认路径、临时目录设置和物理剩余容量。采集时间从同步请求开始计算，避免慢请求把旧证据标成刚采集；未知、过期或不匹配的证据阻断投递。
- Add 使用暂停/停止启动、关闭自动种子管理；实例内同步与投递串行，原子预占及数据库 identity 唯一约束阻止重复活动投递链。UNKNOWN 不自动重放。
- 目标实例在 qui 中禁用或移除后，监控刷新写入 OFFLINE 并返回错误，投递证据采集随之停止。UNKNOWN 对账只处理该同步事件所属实例，不使用其他实例快照，也不因另一个离线实例的 UNKNOWN 阻断当前实例。

该场景验证首次基线不创建任务、两个目标实例分别投递、暂停参数与分类标签、确认后后续任务可继续投递、重启不重复提交、已存在种子不再 Add、物理剩余容量减少后阻断投递，以及不访问未配置实例。

额外针对性测试覆盖 disabled/removed 实例阻断、跨实例 UNKNOWN 隔离和保留外实例活动预占、完整/新鲜容量证据要求、RSS 查询参数保留。启动顺序与采集时间起点已按最终代码路径复核；本轮没有宣称故障注入已覆盖所有启动、退出和慢请求交错。
