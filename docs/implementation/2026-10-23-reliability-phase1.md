# 第一阶段可靠性整改与验证

日期：2026-10-23（Asia/Hong_Kong）。基于 `a89da98` 的工作区改动。

本阶段对应用户提供对照审查中的第一优先级：来源漏处理、消费者边界、确认超时、参与截止和快照清理。以下验证是本地代码与测试验证，未部署本轮后端修改，未新增真实 RSS 批次。

## 已实现

- RSS 发现与消费分离：新增迁移 0019，按站点、feed、来源持久化消费者；发现来源与登记消费者在同一事务提交。
- 临时制品失败可恢复：最多五次尝试、指数退避、两分钟租约、24 小时处理期限；304、RSS 暂时失败、进程重启后仍处理待办。过期租约的旧完成结果不能覆盖新尝试。提交前另补 RecoverOnly：长 RSS 轮询间隔不阻塞到期消费者恢复，恢复不改变 RSS 轮询和验证头状态。
- 重叠 feed 各自评估，最终复用身份对应的 job；UNKNOWN 不自动重投。历史升级来源和首次基线保持跳过，避免重新投递旧条目。因此升级不会自动补投过去已丢失的来源。
- 确认结果、绑定、事件与等待器关闭处于同一事务；任一步失败均可回滚并重新处理。
- 确认超时进入 UNKNOWN；离线时也推进对账期限，到期保留身份及容量占用。重启复用原截止时间，不因重启延期。
- 参与截止覆盖排队、下载后、实例证据采集后、原子预留及发送前边界；数据库写锁取得后读取时钟，等于截止时间视为过期。
- 仅可证明未发送的预留释放容量并结束任务；STARTED、UNKNOWN 等可能已产生远端效果的任务保留确认/对账路径。
- 清理保留等待器、未解决投递链、未释放容量与绑定所需快照；安全终局等待器按保留期限清理。快照清理失败不再阻断后续统计清理；跨批次失败只清理已提交删除批次的文件。
