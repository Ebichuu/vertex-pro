# 第二阶段：制品复用和调度关键路径

日期：2026-10-24（Asia/Hong_Kong）。基于 a89da98 工作区，与第一阶段可靠性整改一起提交。本文件先保留阶段验证记录，再记录提交前补全结果。

## 已实现

1. 新增迁移 0020，将首次 RSS 识别得到的 torrent 原文、SHA-256 和时间与 job/rule snapshot 一并提交。job 创建失败不会留下半条制品记录；同一 job 的制品不得被新内容覆盖。正文不进入 Job JSON。
2. 投递读取原文并验证摘要，再验证真实 hash 和内容大小；损坏时停止，不用网络重新下载替换。旧任务无记录时允许按原路径获取一次，验证身份和大小后冻结；后续等待或阶段重建复用已有内容。
3. 每个制品至多 16 MiB。已结束且没有未释放容量的任务在七天后清理制品；UNKNOWN、EXPIRED_UNKNOWN、未完成和可重试链保留。RECONCILED_NO_EFFECT 在参与截止和最后更新均超过七天、无未释放容量时也可清理。历史 job 及身份记录不随制品删除。
4. 每个调度周期最多四个独立上游组并行；同 site 或同 hostname（含传递关系）的 feed 在同组串行。每个周期仍受 schedulerMu 保护，防止重叠运行；既有 per-feed 轮询间隔、传输层限流和出站校验继续有效。
5. 发送前仍重新检查 qui 实例启用状态、同步快照、确认状态、容量和 preferences。策略停用同步、历史观察、transfer-info 采样留给常规后台 tick，避免成为 Add 的前置附属工作。

## 提交前补全：组选路、恢复和保留边界

- 每个实例在常规后台同步或实时发送前采集后保存一份原始 Evidence。组选路允许复用 30 秒内的结果；命中时必须仍为 READY，generation/revision/digest 与本地数据库完全相同。TTL 从原始采集开始计时，缓存命中不续期；过期、时间倒退、坐标改变或同步失败均不得沿用。访问由 syncMu 保护。
- 仅排名可以使用缓存，选中目标仍强制实时收集、检查启用状态与真实 hash，并在事务内重新计算容量债务。不会缓存 EffectiveFree；UNKNOWN 与 EXPIRED_UNKNOWN 仍计入在途惩罚。没有放松原子预留、发送意图或最终确认边界。
- 已有 hash 的识别先于容量投影；无关任务的剩余量未知、物理空间未知时，不会因此向另一实例重新投递。不能把两台独立 qB 的快照当作全局原子观测：用户在未选中实例上并发手动添加的外部变化，仍可能晚于缓存观测。
- 发送前路径只读取一次 preferences；策略停用、历史与 transfer-info 留在后台。监控采样失败不阻断本轮容量刷新，但清理选路缓存并返回错误，下一次排名回退实时采集。
- 修复每日 RSS 轮询阻塞消费者重试：到期 PENDING 可以独立 RecoverOnly，不抓取 RSS，不改变 last_polled、初始化状态、ETag 或 Last-Modified；禁用 feed/site 和首次基线继续受原规则约束。原 RSS 到期后照常轮询。
- 创建和重复 job 的返回结果不携带 torrent 正文；原文保存到制品存储后及时解除结果引用，避免一个周期的大量 Outcomes 绕过缓存预算。64 MiB 仍只是缓存保留量，不是整个进程的内存上限。
- 新增组选择夹具验证缓存排名与最终实时复核、容量下降拒绝发送、最终 hash 出现零 Add，以及已有 hash 在容量未知时不跨机重投。新增长轮询一分钟恢复、精确退避边界和验证头不变测试，以及 RECONCILED_NO_EFFECT 结束后的清理/可重试和债务保留测试。
